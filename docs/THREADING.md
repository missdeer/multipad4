# 后台任务与并行计算

`src/ThreadPool.h` 是应用和文件层统一的 Windows Thread Pool 入口。
业务模块使用 `work::Submit` 和 `work::ParallelFor`，不自行创建线程。
同步的编辑命令、UI 定时器分时任务仍在调用线程执行。

## 调度

- `Queue::Background`：系统默认池，执行备份、目录搜索工作循环和大文件视图任务。
  回调调用 `CallbackMayRunLong`，告知系统它可能同步读盘、等待计算或等待结果队列空间。
  默认池由 Windows 调节线程数量，没有应用级的固定线程上限。
- `Queue::Compute`：应用共享的专用 Windows 池，最多使用
  `min(8, GetActiveProcessorCount(ALL_PROCESSOR_GROUPS))` 个工作线程。
  用于 UTF-8 校验和大文件搜索的独立分块。
- `ParallelFor` 是同步批次：返回或抛出前，已提交的所有回调都已退出。
  单个任务直接执行；计算回调内的嵌套批次和嵌套计算提交也直接执行，
  避免父任务占满池后等待排队子任务的死锁。

两种队列使用相同的任务封装。背景协调任务可以等待计算池，计算任务不得
反向依赖背景任务完成，也不得等待当前任务自身。

## 结果与生命周期

`Task<T>` 是只能移动的任务所有者，提供 `Valid`、`Ready`、`Wait`、`Get`、`Reset`。
`Get` 取出一次结果并使句柄失效；回调异常被捕获并在 `Get` 时重新抛出。
`Ready` 只检查状态，`Wait` 等待而不取走结果。

任务析构、覆盖赋值和 `Reset` 都先调用
`WaitForThreadpoolWorkCallbacks(work, FALSE)`，再调用 `CloseThreadpoolWork`，
最后释放回调捕获和结果。不能在回调内销毁它自己的任务所有者。
任务对象的检查、移动、取结果和释放应由一个所有者线程执行。

取消采用操作自身的 `atomic<bool>` 标志。所有者先设置标志，唤醒等待结果队列
的工作者，再等待回调退出，最后释放文档、窗口或快照。队列中尚未开始的回调
仍会执行并观察取消标志，确保操作的完成计数和清理逻辑都运行。
自动备份的写盘一旦提交就等待完成，随后决定保留还是删除备份。

## 模块约束

- UTF-8 校验保留分片边界和 SIMD 实现，使用独立任务代替固定工作者屏障。
  调用期间借用的文件视图必须保持有效，批次退出后才能释放。
- 目录搜索每次提交最多 8 个背景工作循环。每个工作者独立持有匹配器，
  文件内部搜索和编码校验串行；结果队列上限仍为 8。
- 大文件搜索保留 64 MiB 分块、字符边界、跨块重叠区和按文本顺序合并结果。
- 大文件视图同时持有一个背景任务，完成后 `PostMessage` 回 UI；应用结果前
  检查快照。取消、换任务和窗口析构都先排空旧回调。
- 普通文档快照搜索和自动备份继续在 UI 中每次提取最多 256 KiB 文本，
  再提交背景任务；UI 定时器使用 `Ready` 检查结果。

## 验证

`thread_pool` 检查任务移动和析构、异常传播、批次失败后的回调排空、
嵌套计算及计算池并发上限和背景队列隔离。`fileio_roundtrip`、`file_search`、
`lazy_document`、`large_file_integration` 和 `editor_integration` 验证业务行为。
